# ADR-0001: Replace execSync shell interpolation with execFileSync argument array in src/checkout.ts

**Status:** Accepted
**Context:** The only vulnerable execution path is `healthProbe` in src/checkout.ts. It builds a shell command string and interpolates the caller-supplied `userAgent` value inside double quotes, which allows shell metacharacters to be interpreted. The test only asserts that `healthProbe("$(id)")` does not return output containing `uid=`. The project uses bun (Node-compatible child_process APIs) and ESM imports, and the constraint is to keep the public signature and test untouched with no new dependencies.
**Decision:** Modify only src/checkout.ts: change the import to `import { execFileSync } from "node:child_process";` and change the body of the exported function to `return execFileSync("printf", ["%s", userAgent], { encoding: "utf8" });`. Keep the export name `healthProbe` and its signature `(userAgent: string) => string` unchanged. Use exactly the argument array `["%s", userAgent]` (format string first, userAgent as a separate argv entry), so the userAgent value is passed as argv[2] to /usr/bin/printf and never reaches a shell. Do not add `spawnSync`, `execSync`, shell quoting, or any WAF/filter logic; do not touch test/checkout.test.ts or package.json.
**Consequences:** `bun test` passes: `execFileSync("printf", ["%s", "$(id)"], ...)` passes the literal string `$(id)` as one argv entry, so printf emits `$(id)` and the output does not contain `uid=`. The single `_test.ts` file and package.json remain unchanged. Only src/checkout.ts changes. No dependencies are added. The fix assumes the runtime's PATH resolves a standalone `printf` binary (POSIX), consistent with the stated assumption that Node-compatible execFile/spawn APIs are available in the bun runtime.
